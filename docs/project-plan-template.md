## How to use this template

- Each major piece of system behavior gets its own `REQ-n` section.
- Each `REQ` is broken into specific, testable `AC-n.m` (acceptance criteria).
- An `AC` should be specific enough that a test can be written directly from it — avoid vague statements like "should work well."
- Mark a `REQ` section's status individually so partial freezing is possible.
- Do not delete old REQs when they change — revise them and note the change in the changelog at the bottom, so there's a record of what shifted and why.
